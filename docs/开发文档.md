## 1. 任务、边界与执行原则

### 1.1 要开发的产品

开发一套中文学生成绩管理系统，服务管理员、教师、辅导员、学生四种角色。包括账户管理、教学基础数据、学生档案、成绩维护、授权查询、成绩统计、Excel 导入导出、个人中心、头像、登录保护、令牌黑名单和操作审计。

必须交付真实前后端与 MySQL 数据持久化。开发过程中的模拟数据只用于独立测试，不可作为最终业务接口。界面必须可操作，不能仅交付静态页面、接口骨架或只有成功分支的演示。

### 1.2 严格独立实现

1. 本规格编写时已经参考原项目的配置、源码和说明，用来提取业务事实；此权限仅适用于编写本文。
2. 新系统的设计、编码、修复和测试阶段，严格禁止访问、检索或参考原系统的任何源码、SQL、样式、配置、测试、构建产物、Git 历史以及含旧实现细节的 AOCI 索引。
3. 后续开发依据仅为本文、新项目自己产生的文档/代码，以及所用技术和第三方组件的官方资料。不可要求开发者返回原仓库“再核实功能”。
4. 禁止复制再改名、逐文件翻译、沿用旧目录拆分或先生成高度相似实现再修改以降低相似度。应从本文的领域模型和契约独立推导实现。
5. Java/Spring/Vue 的必要语法、标准框架惯例、业务名称和数学公式允许自然相同。独立实现不以随机改名、绕开框架惯例或人为制造差异为目标。
6. LeiBox 等明确允许的第三方组件可按其许可使用，记录来源并保留声明。第三方组件使用许可不等于允许复用原系统代码。
7. 新项目使用新的仓库、包名、数据库和 AOCI 资产。不得复制原系统 AOCI 索引，也不得使用真实学生资料或旧项目凭据作初始化数据。

### 1.3 事实与新设计的区分

本文提取出的原项目能力包括：四角色、JWT 认证、限流、黑名单、个人中心、学院/班级/课程维护、成绩管理及导入导出、仪表盘、四类 AOP 职责、MyBatis-Plus、Lombok 和 COS 头像。

以下属于本规格为独立重写给出的新设计基线，并非宣称原系统已经具备：统一身份与学生档案绑定、稳定 ID 关联、统一接口及分页、完整的授权关系维护入口、学生档案维护入口、事务内派生统计一致性、可靠令牌撤销、统一成绩规则及导入错误报告。

原项目中不一致或不安全的行为不作为兼容目标。第 14 节说明具体取舍。实现时遵循本文已经给出的统一规则；仅对本文确实未定义且影响核心行为的事项提出针对性问题，其他工作持续推进。

## 3. 角色、数据范围与功能清单

### 3.1 角色规则

每个账户在本期只有一个角色：`ADMIN`、`TEACHER`、`COUNSELOR`、`STUDENT`。不增加自助注册、角色自由切换或自选权限功能。

账户内部 ID、学号/工号、登录用户名是三个不同概念。学生账户通过显式关联绑定学生档案，不能假定账户 ID 就是学号。学号和工号使用字符串，以保留前导零及避免 JavaScript 数字精度问题。

| 能力 | 管理员 | 教师 | 辅导员 | 学生 |
|---|---|---|---|---|
| 账户创建、编辑、启停、删除、重置密码 | 全部账户 | 无 | 无 | 无 |
| 用户 Excel 导入导出、批量创建学生账户 | 有 | 无 | 无 | 无 |
| 学院、班级、课程、学期、学生档案维护 | 有 | 无 | 无 | 无 |
| 分配教师课程/班级、辅导员班级 | 有 | 无 | 无 | 无 |
| 学生列表 | 全部 | 授权班级 | 负责班级 | 不提供其他学生列表 |
| 成绩列表、详情、统计 | 全域 | 授权班级中的授权课程 | 负责班级的全部课程 | 本人全部课程 |
| 成绩新增、修改、删除、批量新增 | 有 | 授权范围 | 无 | 无 |
| 成绩 Excel 导入导出 | 有 | 授权范围 | 无 | 无 |
| 个人资料、用户名、密码、联系资料、头像 | 本人 | 本人 | 本人 | 本人 |
| 审计记录业务页面 | 本期不强制；日志记录和可验证查询能力必须存在 | 无 | 无 | 无 |

教师拥有独立的课程集合和班级集合；可操作成绩的条件为“学生属于其授权班级”且“课程属于其授权课程”。本期按两个集合的交集过滤，不额外引入按学期的授课分配规则。教师详情、汇总、导出和统计也必须受相同范围限制。

未分配班级或课程时，教师对应查询返回空集合；辅导员未分配班级时返回空集合。空授权集合绝不能被解释为“不限制”。

用户名与学号/工号之间不允许形成跨账户登录歧义。例如一个账户的用户名不能等于另一账户的学号。数据库与应用共同保证登录标识解析唯一。

业务号和学号创建后不在普通资料更新中修改；学生账户的业务号必须与所绑定档案的学号一致。新项目必须明确用户名大小写规范并在登录、可用性检查和唯一约束中统一执行，不允许依靠不同入口采用不同大小写规则。

## 4. 成绩与统计规则

### 4.1 成绩输入

成绩记录由学生、课程、学期、记录学分、考核性质和百分制分数组成。

- 同一学生、课程、学期只能有一条成绩。重修如发生在其他学期可另建一条；本期不设计同学期多次考试记录、补考审批或成绩发布工作流。
- 新增/修改/导入要求分数为 0–100 的数值，最多两位小数；拒绝空白、NaN、无穷大及非法字符串，不把错误值转成 0。
- 学分非负、最多两位小数。默认取课程默认学分，但记录保存学分快照，后续课程学分调整不追改历史成绩。
- 考核性质仅允许 EXAM（考试）与 ASSESSMENT（考查）；前者有效权重等于学分，后者为学分的一半。
- 学生、课程、学期必须存在；班级与学院关联必须一致。GPA、排名、人数和汇总值由服务端计算，不接受客户端覆盖。
- 学期使用稳定 ID，并以学年与学期序号排序，不按任意中文名称字典序排序。
- 无成绩用空集合与 null 统计表达，前端显示“—”；有效零分显示 0，二者不可混淆。

### 4.2 单科 GPA

GPA 按连续分数区间计算，避免小数分值落在文字区间空隙：

| 分数区间 | GPA |
|---|---|
| [90, 100] | 4.0 |
| [85, 90) | 3.7 |
| [82, 85) | 3.3 |
| [78, 82) | 3.0 |
| [75, 78) | 2.7 |
| [72, 75) | 2.3 |
| [68, 72) | 2.0 |
| [64, 68) | 1.5 |
| [60, 64) | 1.0 |
| [0, 60) | 0.0 |

校验分数合法性后再计算 GPA。计算发生在服务端，前端仅显示结果。

### 4.3 学生明细与汇总

先按角色数据范围、学期及请求筛选条件确定记录集合，再计算：

- 课程/成绩记录数：该集合的记录数量；另提供去重课程数，字段和文案不得混用。
- 总分：分数之和。
- 算术平均分：总分 / 记录数量。
- 加权平均分：Σ（分数 × 有效权重）/ Σ（有效权重）。
- 平均学分绩点：Σ（单科 GPA × 有效权重）/ Σ（有效权重）。
- 总学分：Σ（记录学分），不因考查性质减半。
- 已通过学分：分数不低于 60 的记录学分之和，独立于总学分。
- 不同学期的同一课程按不同成绩记录参与统计；本期不额外应用“仅最高成绩计入”等未定义规则。

成绩、学分和 GPA 使用十进制定点计算；只在最终结果舍入。分数、加权平均和 GPA 结果保留两位小数，HALF_UP；仪表盘平均分和通过率显示一位小数。分母为 0 时结果为 null，不返回 NaN、不伪造绩点为 0；计数和学分合计可为 0。

### 4.4 排名和人数

- 班级排名以学生在同一统计范围内的未舍入加权平均分降序计算；相同值并列、跳过后续名次，即 1、1、3。
- 支持按学期排名与全部学期排名，二者不能混用；前端必须显示当前统计范围。
- 无成绩或只有零权重记录的学生不参与排名，其排名为 null。
- 一人成绩变化可能改变同班其他学生名次，必须重算整个受影响班级与学期的排名，不能只更新被修改者。
- 学生调班时，在事务前取得原班级，并更新新旧班级人数和相关排名；删除、批量新增也适用。
- 人数统计针对未删除的学生档案，和账户是否禁用无关。
- 教师不可通过排名或全域汇总泄漏未授权课程信息。教师只得到其课程范围内的统计，班级完整排名仅向管理员、对应辅导员和本人提供。

### 4.5 仪表盘

提供：有成绩学生数、成绩记录数、算术平均分、及格率、加权平均、总体 GPA、成绩分布、课程平均分与记录数、按学期的平均分/GPA 趋势。

成绩分布分为 [90,100]、[80,90)、[70,80)、[60,70)、[0,60)。及格率为分数 ≥60 的记录数 / 全部匹配成绩记录数 ×100。有成绩学生数按学生去重，不等于班级在籍学生人数。

总体 GPA 直接在可见记录集合内按有效权重计算，不计算“每个学生 GPA 再简单平均”。列表、详情、图表与导出须使用同一套服务端规则。前端不得另写一套权威统计公式。

### 4.6 可直接使用的验收样例

同一学生、同一学期有两门课：A 为考试课，3 学分、90 分；B 为考查课，2 学分、60 分。

预期：有效权重分别为 3 和 1；总分 150；算术平均 75；加权平均 82.50；GPA 为 (4×3+1×1)/4 = 3.25；总学分及通过学分均为 5；记录数 2。

将 B 改为 50 分：总分 140；算术平均 70；加权平均 80.00；GPA 3.00；总学分 5、通过学分 3。删除 A 后：只剩 B 的统计，加权平均 50、GPA 0、总学分 2、通过学分 0。

三名同班学生的未舍入加权平均为 90、90、80，排名必须为 1、1、3。把第三名改为 95 后，三人相应排名变为 2、2、1。

## 5. 新架构与数据库设计

### 5.1 架构基线

采用模块化单体后端与一个支持四角色工作台的 Vue 应用。角色体验、导航与页面权限保留，避免四份重复前端。此前的四个前端工程数量不属于必须保持的技术栈。

后端按身份与权限、教学基础资料、学生档案、成绩与统计、文件/导入导出、审计划分职责。每个领域内部区分接口 DTO、应用服务、领域规则与持久化适配；Controller 不直接编排数据库事务，不把业务计算写在 Mapper 或前端。

前端按应用入口/路由、领域页面、业务 API、共享业务组件、基础组件、组合函数、设计变量划分。共享层不能反向依赖某一角色页面。建立一套请求客户端、错误映射与认证状态管理。

以下是职责约束，不要求为了形式创建大量空包或公共抽象：

- API 层：参数校验、身份读取、返回契约。
- 应用服务：权限/数据范围、用例编排、事务及 AOP 入口。
- 领域计算：GPA、权重、汇总、排名规则；可独立调用与验证。
- 基础设施：MyBatis-Plus、Redis、COS、POI 和日志适配。
- 数据库：引用、唯一性、值域与并发写入的最后一道一致性约束。

### 5.3 约束、索引与删除

1. 成绩分数 NOT NULL 且在 0–100 之间；学分非负；角色、状态、考核性质具有值域约束。跨表的角色/班级学院一致性由应用服务在事务内验证。
2. 成绩索引至少覆盖学生+学期、课程+学期及唯一键；学生索引覆盖班级、学院；授权关系按账户查询；审计按时间、操作者+时间、模块+时间查询；撤销记录按过期时间清理。
3. 班级有学生、课程有成绩、学期有成绩时拒绝删除。学院仍被引用时拒绝删除。不能用名称变更或级联删除破坏历史成绩。
4. 教师授权关系可明确解除并保留操作审计；删课程前处理相关授权关系，不能静默连带改变权限。
5. 新增/编辑均检查唯一性，但以数据库唯一约束处理并发竞态，冲突转为稳定的业务错误。
6. 成绩更新携带 version；两个客户端修改同一记录时，后提交者收到冲突，不能静默覆盖。
7. 提供空库初始化、按版本迁移及独立演示数据；初始化不删除已有库。本文不要求导入旧系统真实数据或编写旧库迁移工具。
8. 维护数据字典，写清每个字段类型、长度、NULL/默认值、枚举、索引及外键动作。不能只给一张 ER 图就宣布数据设计完成。

## 6. 必须真正实现的 AOP 与事务

必须有可观察生效的切面，不能用“以后补充”或只添加依赖代替。可以让切面调用独立领域服务完成计算，不要求模仿旧类名、切点表达式或方法布局。

| 编号 | 切面职责 | 触发与结果 |
|---|---|---|
| AOP-01 | 单科 GPA 计算 | 成绩新增、更新、批量新增/更新、Excel 导入写入前，统一校验并计算 grade_point |
| AOP-02 | 成绩派生数据同步 | 成功写入或删除成绩后，重算受影响学生的 ALL/学期汇总及相关班级排名；修改所属学生/课程/学期时处理旧新范围 |
| AOP-03 | 班级人数同步 | 学生新增、更新、调班、删除、批量录入成功后，更新受影响新旧班级人数；调班同时修正汇总排名 |
| AOP-04 | 操作审计 | 登录/退出，账户维护、启停、重置/生成，基础数据/授权/学生/成绩写入，导入导出，个人资料与头像修改，记录成功和失败 |

必须满足以下实现约束：

- 使用明确的应用服务写入入口或自定义注解建立切点；必须验证 Spring 代理真实经过切面。禁止依赖同类 self-invocation 触发代理。
- 所有写入入口，包括批量与导入，都进入相同业务和切面链；不能仅网页按钮路径生效。
- 事务代理包住成绩写入、GPA 计算和派生更新，派生更新失败时业务一起回滚。明确切面顺序，避免提交成功后才同步造成已返回成功但数据不一致。
- 普通数据库写入失败或返回无修改结果时，不做成功同步；不能把无条件 finally/@After 当作成功依据。
- 删除与调班前取得旧归属；修改成绩时同时考虑旧新学生、旧新学期。批次对受影响学生和班级去重，但排名需更新整个受影响集合。
- 同一班级/学生并发变更要避免派生数据被旧快照覆盖。统一锁顺序或同等一致性方案必须写入 ADR 并以并发用例验证。
- 统计更新调用不得再次触发成绩写入切面导致递归。
- 审计成功状态以事务最终结果为准，不只看方法是否返回。业务回滚时不能留下“成功”审计。
- 失败审计应能在业务回滚后单独保留；审计自身落库失败记录脱敏的系统错误，不替换原业务异常。该降级不适用于成绩派生更新失败。
- 日志不保存密码、密码摘要、验证码答案、完整 JWT、COS 密钥或导入文件的全部敏感内容。

## 7. 认证、黑名单与文件安全

### 7.1 认证与凭证生命周期

JWT 至少包含唯一 token ID、账户 ID、角色、签发/到期时间、auth_version；默认有效期保留为 7 天，可配置。签名密钥由新项目本地配置提供，不复制旧密钥，不保留可用于真实环境的默认秘密。

每个受保护请求校验签名、有效期、账户存在/状态、当前角色/版本及撤销状态。客户端提交的角色、学号、账户 ID 或前端缓存不得决定授权。

改密码、重置密码、禁用、删除或改角色时增加账户 auth_version；所有旧版本令牌被拒绝。授权关系变化按实时关系判断，不把过期的课程/班级集合永久写入令牌。

登录验证码由服务端生成、保存答案摘要、校验并消耗；验证码错误明确提示，重复使用无效。开发验证采用隔离的测试账号和受控夹具，不能在正式认证链中留下永久通用验证码。

限流计数采用原子更新与到期语义；同一账户的用户名/业务号不能各获一套可绕过的次数。登录计数窗口为首次失败起 15 分钟，达到第 5 次时锁定 15 分钟；资料验证窗口为 5 分钟，达到第 3 次时锁定 5 分钟。锁定期间不验证密码；成功后清理对应计数。实现必须区分“未锁定”和“存储不可用”。

### 7.2 黑名单基线

默认保留 Redis，并采用 MySQL 撤销记录作为可靠事实来源、Redis 缓存已撤销 token ID：

1. 退出先提交 MySQL 撤销记录，再尝试写 Redis，TTL 为令牌剩余有效期。重复退出对同一 token ID 幂等。
2. Redis 命中未过期撤销记录时拒绝；Redis 未命中或不可用时查询 MySQL。不能把缓存未命中等同于未撤销。
3. MySQL 无法确认账户或撤销状态时拒绝受保护请求，并返回服务不可用语义；不能因缓存故障放行已注销令牌。
4. MySQL 撤销提交失败则退出接口返回失败，不能宣称服务端已注销；前端可清理本地登录态，并准确提示状态。
5. Redis 写入失败但 MySQL 已持久化时，撤销已生效，可返回退出成功，同时记录缓存故障。
6. 不记录完整 token 作为缓存键或日志字段，使用不可逆令牌标识或随机 jti。所有节点共享 MySQL 撤销事实，应用重启不复活已注销令牌。
7. 定期清理过期撤销记录。到期 JWT 由认证校验拒绝，不依赖黑名单清理时机。
8. 本期 Redis 故障时登录/资料限流不得静默关闭；无法可靠取得计数则相关验证入口返回服务不可用，其他可确认安全的业务按上述规则继续。

退出的幂等性需要在认证入口专门处理：签名正确且未过期、但已在黑名单中的当前令牌，可再次调用仅执行撤销的退出接口并返回成功；不能因此放行其他受保护接口。无效签名仍拒绝，过期令牌可以返回“已失效”的幂等结果，不产生可用身份。

用户允许未来以等价存储替换 Redis，但本规格默认实现 Redis；替换必须先形成 ADR，证明原子限流、到期与撤销安全行为等价。不得把该可选项当作减少黑名单功能的理由。

### 7.3 头像

- 默认最大 2 MiB，允许 JPEG、PNG、GIF、WebP；同时检查声明 MIME、文件内容和实际类型，扩展名不能决定是否安全。
- 文件为空、超限、伪造类型、无效图片或不能解析的内容均拒绝；WebP 必须验证实际 WebP 内容，不能仅凭 RIFF 前缀放行。
- 对象路径由服务端生成并绑定 owner；删除只能作用于本人已登记对象，不接受任意 URL 或其他用户 object key。
- 替换顺序为上传新对象 → 更新头像引用 → 清理旧对象；上传或数据库更新失败时保留可用旧头像，并清理可能产生的新孤儿对象。
- 清理旧对象失败不破坏新头像，记录可重试事项。移除头像后页面恢复默认头像。
- COS 适配器与开发文件适配器遵守相同接口，敏感存储参数不可返回前端。

## 8. 新 API 契约

### 8.1 统一约定

使用新接口前缀 `/api/v1`。新前后端一起实现，不要求旧 URL、字段名或响应包装兼容。

JSON 响应字段：`code`（稳定字符串业务码）、`message`（简明用户提示）、`data`、`traceId`。成功 code 为 OK；HTTP 状态与语义一致：400 参数错误、401 认证无效、403 权限不足、404 可见资源不存在、409 重复/版本/引用冲突、429 限流、503 依赖不可用、500 未知错误。错误不能返回数据库报错、堆栈或秘密字段。

分页请求为 page（从 1 开始）、pageSize（默认 20、最大 100）、排序白名单和相关过滤字段。响应 data 为 items、total、page、pageSize。查询范围过滤、排序和分页在服务端完成，total 必须是相同权限与筛选条件下的总数。

多角色共同接口由服务端按当前身份缩小范围；管理员维护接口统一限制 ADMIN。所有成绩对象读取/修改/删除必须校验对象实际归属，更新还校验目标新归属，禁止只根据请求体声称的学生/课程通过授权。

## 9. Excel 导入导出

### 9.1 成绩文件

模板列：学号、课程名称、学分、考核性质、学期编码、成绩。考核性质接受“考试”或“考查”，模板固定列名并给出新项目的独立样例。导出可额外包含系统记录 ID，但导入不得信任文件 ID 来覆盖既有记录。

学号按文本读写，不能转为 int、科学计数或丢弃前导零。课程名称与学期编码必须唯一解析；非法数字、空必填单元格、重复行、库内重复、未授权学生/课程均报告 Excel 行号与原因。

成绩导入与批量新增采用全有或全无：先完整解析和校验，再事务写入；任何行失败，整个批次不写入，不吞异常伪装成功。不默认 upsert、不静默覆盖原成绩。

### 9.2 用户文件

模板列：学号/工号、用户名、姓名、邮箱、手机号、角色、状态。初始密码作为独立管理员输入参数，不从导出文件回填，不在日志中记录。导入 STUDENT 账户时，必须按学号绑定已经存在且未绑定的学生档案；缺档案或冲突报告失败。

本期用户导入按行提交：重复已有身份跳过，合法新行创建，错误行失败；返回 total、created、skipped、failed 和各行状态/原因。再次导入已创建行不重置密码。状态只接受“启用/禁用”，角色只接受四种枚举，未知内容不得默认为管理员或启用。

### 9.3 文件与反馈

仅接收真实 xlsx，默认最大 10 MiB、10000 条数据行；限制解析资源，拒绝非法文件，不执行公式或宏。导出对用户提供文本按文本单元格写入，避免被解释为公式。

导出反映当前角色与筛选条件下全部记录；导入弹窗显示真实结果与错误行，不显示虚假百分比。所有文件流/工作簿正确关闭。限额、列格式与批次原子性必须写进新 API 文档。

## 10. 全新前端规格与美观性验收

### 10.1 信息架构

使用统一登录入口和一个应用外壳，按角色生成菜单：

| 角色 | 导航 |
|---|---|
| ADMIN | 概览、账户、学生、学院与班级、课程与学期、成绩、个人中心 |
| TEACHER | 概览、成绩、学生成绩查询、个人中心 |
| COUNSELOR | 概览、班级成绩、学生成绩查询、个人中心 |
| STUDENT | 概览、我的成绩、个人中心 |

授权管理放在对应教师/辅导员账户详情中。学生详情可包含档案、账户绑定、成绩和排名，但角色只看到允许的字段与操作。成绩录入、导入、导出等围绕当前任务集中组织，避免无意义的重复页面。

后台数据由 API 驱动；筛选、分页、排序、删除后的页码回退和错误重试有一致行为。切换筛选条件重置页码；处理旧请求晚返回覆盖新查询的问题。

### 10.2 Apple 式简洁高效的具体要求

- 使用清晰留白、稳定网格、克制圆角、细边界与轻层次；中性表面色配一种主要强调色。字体使用系统字体，不下载或复制专有字体资产。
- 层级主要依靠字号、字重、间距和分组。每个工作区一个明确主操作，危险操作清楚但不过分抢眼。
- 不使用大面积渐变、发光、玻璃特效、粒子、悬浮装饰或与任务无关的动效；不堆叠仪表盘卡片填满空白。
- 页面主标题后不添加重复解释的小字；没有实际信息的“欢迎使用”“高效管理平台”等文案不出现。
- 可见小字仅用于真正必要的单位、状态或即时错误；表单保留准确标签，复杂规则按需在帮助或校验错误中呈现。
- 表格支持快速扫描、必要列固定/溢出处理、空/错误/加载状态；复杂长表在窄屏以合理方式滚动，不能让页面整体横向失控。
- 语义清楚的操作用文字或图标加可访问名称，不能为了极简把所有操作变成无说明图标。
- 支持键盘导航、可见焦点、表单标签、错误定位、合理对比度、减少动态效果偏好；不得删除安全提示或必要帮助来追求视觉简洁。

### 10.3 LeiBox 使用要求

前端实施时读取宿主的 `leibox` 技能，用实时目录按“导航、筛选、任务反馈”等实际用途检索，限定 Vue，阅读少量匹配组件的详情、依赖、来源与使用限制。

通常选 1–3 个有实际价值的组件，不强制使用某个名称或固定数量；不适配时使用 Element Plus 或独立实现。下载成功不代表完成，必须验证真实状态、键盘、卸载清理与异常回退。

将查询、选型理由、来源、接入位置、许可和限制写入 `docs/COMPONENT_SOURCES.md`。LeiBox 用于改善交互，不为凑数量引入装饰。

### 10.4 ego-browser 审查

在本地启动的新系统中，用 ego-browser 检查实际渲染页面。至少覆盖 1440×900、1280×800、768×1024、390×844 四种视口，以及：

1. 登录与验证码、四角色首页和主要导航。
2. 管理员账户/学生/基础资料表格与弹窗；教师成绩编辑和导入结果。
3. 辅导员只读流程、学生本人查询、个人中心及头像。
4. 长名称、空数据、加载、请求失败、校验错误、无权限和登录过期。
5. 键盘 Tab/Enter/Esc、弹层焦点、遮挡裁剪、对齐、按钮密度和窄屏溢出。

审美标准不是“页面能打开”。记录页面/角色/视口、截图、具体问题、修复及复查结果。没有实际操作的页不能写已通过。只有构建成功时不能宣称美观性验收完成。

### 11.1 开发顺序

- 安装/初始化/scan 与首次语义索引建立按当前技能、aoci_rules 和实时 Guide 执行。不硬编码旧版命令或把扫描清单当完整语义。

## 14. 编写本规格时的逻辑核验与差异处理

本节解释哪些内容来自实际项目，哪些是为了得到可独立开发规格而作出的设计决定。它不要求后续开发者访问旧仓库。

| 观察/歧义 | 本规格的处理 | 性质 |
|---|---|---|
| 旧教师列表限制课程，但学生详情仅校验班级 | 所有教师查询、明细与统计统一按班级和课程交集过滤 | 明确收紧数据边界，避免不同入口泄漏 |
| 旧学生身份依赖账户 ID 与学号相同 | 新账户与档案显式绑定，用户名可变但学生身份不变 | 新身份模型 |
| 旧班级、课程等存在名称关联 | 采用稳定 ID、展示名可改、历史成绩不失联 | 数据库重新设计 |
| 旧 GPA、总分、详情与排名分布于多个位置 | 后端统一公式，明确空数据、零权重和舍入，前端不重复权威计算 | 统一计算契约 |
| 旧调班切面在更新后读取“旧”班级 | 写入前读取旧归属，事务内更新新旧范围 | 避免时序缺陷 |
| 一人成绩变化会影响同班其他人的排名 | 重算受影响班级和学期，而非只写一个人的排名 | 完整一致性要求 |
| 旧 Redis 不可用时黑名单可能放行 | MySQL 撤销事实 + Redis 加速，无法确认时拒绝 | 可靠安全行为 |
| 旧登录验证码由客户端处理 | 服务端一次性验证码，保留交互且确保可验证 | 新安全设计 |
| 旧用户导入/生成可能使用固定弱密码 | 管理员提供合规临时密码、首次改密、不覆盖旧账户 | 统一密码规则 |
| 旧头像替换先删除旧对象 | 新对象与引用成功后再清旧对象 | 保留失败恢复能力 |
| 原数据与服务已有学生/授权关系，维护入口不完整 | 新增必要管理员维护入口，贯通系统生命周期 | 新设计补齐 |
| 旧依赖声明不等于新组合兼容 | 只固定技术栈，首轮核验并锁定实际依赖 | 不虚报兼容性 |
| 原验收记录仅部分角色通过 | 新系统按本文独立验收，不继承旧 PASS 结论 | 证据范围约束 |

核验重点是需求可实现、行为完整、数据范围一致和状态变化闭环；不以文字变长、文档格式完善或测试数量多作为逻辑正确的证明。本规格没有宣称已经完成新系统运行验证。
